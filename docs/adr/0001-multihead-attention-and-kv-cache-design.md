# Rank-polymorphic core ops for multi-head attention; stateless, growing-cache KV cache

**Status**: accepted

Implementing real multi-head attention (M7) requires `Tensor` to support a per-head split — `[seq, embed_dim]` reshaped and permuted into `[num_heads, seq, head_dim]` — and matmul/softmax/masking to operate over that leading head dimension. Rather than add a narrow, attention-only path (a separate `bmm`, a hand-looped per-head softmax, a one-off split/merge helper with its own hardcoded `grad_fn`), we extended the core ops themselves to be rank-polymorphic: `matmul` handles rank-2 and rank-3 (looping the leading dimension) under one name, `softmax` and the causal mask do the same, and `reshape`/`permute` — previously missing autograd wiring entirely — were fixed at the source with a generic N-dimensional index walker, rather than only patched for the ranks attention happens to need. This is more work up front and required re-verifying `reshape`/`permute` for every existing caller (both were silently non-differentiable before this), but keeps `Tensor`'s API honest and avoids the framework accumulating one-off, attention-shaped exceptions to its own general ops.

The rank-3 leading dimension is explicitly named "head dimension," not "batch dimension" — this framework has no training-batch dimension anywhere yet, and reusing "batch" for attention heads would collide with that meaning once minibatching is eventually added.

Separately: the KV cache is a standalone `KVCache` object passed into `SelfAttention::forward(input, cache)`, not state stored inside `SelfAttention` itself. Every `Layer` in this framework is currently a pure function of its input and learned parameters (`Linear`, `GELU`, `Sequential`); making `SelfAttention` stateful would break that invariant and risk stale/shared cache bugs across training vs. generation or across separate generation runs. `CharModel` (or whatever drives generation) owns and threads one `KVCache` per transformer block explicitly.

For M7, `KVCache` grows by concatenating each new step's K/V rather than writing into a preallocated `max_seq_len` buffer — no `Tensor` concat-along-axis op exists yet, and a fixed cap is a premature API decision (what happens at the limit?) before generation is even proven correct once. `KVCache`'s external interface (append/get) is kept stable so the internals can switch to a preallocated buffer later (naturally motivated by M8/SIMD profiling, or sooner) without touching call sites.
